# Определение ориентации текста — E5 cascade

Решение предсказывает вероятность того, что текстовый crop повёрнут на 180°.
Итоговый файл — `submission.csv` с колонками `image_id` и `p_180`.

## Подход

1. Две компактные модели ориентации обрабатывают исходное изображение и его
   копию, повёрнутую на 180°.
2. Три OCR-модели сравнивают уверенность чтения в обеих ориентациях.
3. Эти сигналы объединяются в базовый прогноз E2.
4. Если уверенность E2 не ниже `0.85`, прогноз сохраняется без изменений.
5. Для остальных сложных изображений подключаются English OCR, Latin OCR и
   PP-OCRv6-small. Их сигналы уточняют только этот небольшой хвост.

Поворот меняет классы местами, поэтому прогнозы исходника и R180 объединяются
в пространстве логитов. Это встраивает полезное свойство:
`p(R180(x)) = 1 - p(x)`.

Результаты на закрытом тесте Avito:

- E2: `0.98662396`;
- E5 cascade: `0.98809675`;
- уменьшение Brier error: около `11%`.

## Файлы

- `solution.ipynb` — краткое описание и удобный запуск по ячейкам;
- `run.py` — весь inference в одном читаемом Python-файле;
- `config.json` — зафиксированные веса, масштабы и порог `0.85`;
- `e1_model/` — веса дообученной модели ориентации;
- `submission.csv` — отправленный результат;
- `requirements.txt` — версии библиотек.

## Запуск

Проверено на Python 3.12, Windows и NVIDIA GPU. Из папки с решением:

```powershell
python -m pip install paddlepaddle-gpu==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cu129/
python -m pip install -r requirements.txt
python run.py --images ..\images --sample ..\sample_submission.csv --output reproduced_submission.csv
```

Официальные OCR-модели Paddle скачиваются автоматически при первом запуске.
Можно также открыть `solution.ipynb`, изменить пути в ячейке «Параметры» и
выполнить notebook сверху вниз.

Режим `exact` используется по умолчанию и воспроизводит отправленный CSV.
Он сохраняет исходный размер batch для дополнительных OCR, поскольку
предобработка PaddleOCR немного зависит от состава batch. Режим `sparse`
быстрее и действительно отправляет в дополнительные OCR только сложные crop,
но может дать небольшие численные отличия:

```powershell
python run.py --images ..\images --sample ..\sample_submission.csv --mode sparse
```

## Проверки и воспроизводимость

Перед сохранением код проверяет:

- точные названия и порядок колонок;
- совпадение ID и их порядка с `sample_submission.csv`;
- отсутствие дубликатов и NaN;
- диапазон вероятностей `[0, 1]`;
- ровно 20 000 строк для полного официального sample.

Полный exact-прогон был сравнен с отправленным файлом:

- сложных изображений: `942` из `20 000`;
- максимальная абсолютная разница: `9.11e-7`;
- средняя абсолютная разница: `1.65e-8`;
- различий в классе при пороге 0.5: `0`;
- пропущенных или лишних ID: `0`.

`seed = 20260920` сохранён в конфигурации. Inference детерминирован; небольшой
предел численного совпадения связан с GPU-операциями и batch preprocessing.

## Производительность

На RTX 5070 exact-воспроизведение занимает примерно 37 минут. Sparse-режим —
около 12–13 минут. Размеры файлов моделей: orientation `6.5 + 6.5 MB`, базовые
OCR `16.4 + 7.7 + 7.8 MB`, дополнительные OCR `7.6 + 7.8 + 20.5 MB`.

Качество было главным критерием; cascade одновременно ограничивает применение
дополнительных моделей сложными примерами.

## Данные, модели и инструменты

Использованы локальные open-source модели PaddleOCR/PaddleX:

- `PP-LCNet_x1_0_textline_ori`;
- `PP-OCRv5_mobile_rec`;
- `eslav_PP-OCRv5_mobile_rec`;
- `cyrillic_PP-OCRv5_mobile_rec`;
- `en_PP-OCRv5_mobile_rec`;
- `latin_PP-OCRv5_mobile_rec`;
- `PP-OCRv6_small_rec`.

Для обучения и проверки применялись публичные Paddle orientation data, IIIT5K,
ICDAR2015 и MIT-лицензированный RU/EN synthetic dataset. Test labels не
использовались, ручной разметки test не было, внешние inference API не
использовались.

Coding/research agents помогали с поиском гипотез, автоматизацией экспериментов,
проверками и документацией. Финальные коэффициенты зафиксированы в
`config.json`; leaderboard не использовался для их обучения.
